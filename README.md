# 두도 포인트 – 부산 두도·인근 갯바위 낚시 확률 앱 (안드로이드 + 웹)

## 웹 버전 (GitHub Pages)

`docs/index.html` 한 파일이 웹 버전입니다. 안드로이드 앱과 같은 점수 모델을 자바스크립트로 옮겼고, 실시간 예보는 Open-Meteo(키 불필요)에서 받습니다.

1. GitHub 저장소 → **Settings → Pages**
2. Source: **Deploy from a branch**, Branch: **main**, 폴더: **/docs** → Save
3. 1~2분 뒤 `https://boogie23-creator.github.io/dudo-fishing/` 에서 열림

- 바람·파고·수온·해수면(만조·간조)을 Open-Meteo에서 자동으로 받고, 못 받으면 직접 입력 모드로 동작합니다.
- 화면을 수정하려면 `web/src.html`을 고친 뒤 `python3 web/build.py` 로 `docs/index.html`을 다시 만듭니다. 포인트·조과 데이터는 앱의 `points.json`, `catches.json`을 그대로 씁니다.


그날의 날씨·물때·수온·시간대를 점수(0~100)로 계산해서 **어느 포인트에서, 몇 시에, 어떤 어종을 노리면 좋은지** 순위로 보여주는 앱입니다.

## 1. 실행 방법

1. [Android Studio](https://developer.android.com/studio) 설치 (최신 버전)
2. 압축을 풀고 Android Studio에서 **File → Open → `DudoFishing` 폴더** 선택
3. 처음 열면 Gradle 동기화(필요한 라이브러리 다운로드)가 몇 분 걸립니다
4. 휴대폰을 USB로 연결(개발자 옵션 → USB 디버깅 켜기)하거나 에뮬레이터를 고른 뒤 ▶ 실행

### GitHub에서 APK 받기 (Android Studio 없이)

`main` 브랜치에 push하면 GitHub Actions가 자동으로 APK를 빌드합니다.
저장소의 **Actions** 탭 → 최신 "Build APK" 실행 → 아래쪽 **Artifacts**의 `dudo-fishing-debug-apk`를 내려받아 압축을 풀고 휴대폰에 설치하세요(출처를 알 수 없는 앱 설치 허용 필요).

API 키가 없어도 **데모 모드**로 바로 동작합니다(날씨는 가상 데이터, 물때는 달 위치로 추정).

## 2. 실제 데이터 연결 (API 키 발급, 무료)

| 데이터 | 발급처 | 앱 설정 칸 |
|---|---|---|
| 풍속·풍향·파고·강수 | 공공데이터포털 data.go.kr → "기상청_단기예보 조회서비스" 활용신청 | 기상청 인증키 |
| 만조·간조 시각 | 공공데이터포털 "국립해양조사원_조석예보(고, 저조)" 활용신청 (같은 키, 부산 DT_0005). 없으면 해수욕장 서비스 조석정보(송도해수욕장) → 달 위치 추정 순 | 자동 |
| 수온 | 공공데이터포털 "기상청_전국 해수욕장 날씨 조회서비스" 활용신청 (단기예보와 **같은 키**) | 자동 – 두도에서 가장 가까운 송도해수욕장(268번, 3.5km) 부이 실측. 관측이 없으면 몰운대(164)·다대포(308)·감지해변(165) 순으로 시도, 모두 없으면 월평균 추정. 해변코드 표는 `assets/beaches.json` |

- 앱 오른쪽 위 ⚙ 설정에서 키를 붙여넣고 저장하면 됩니다.
- **키를 앱에 기본으로 넣기(추천)**: GitHub 저장소 → Settings → Secrets and variables → Actions → *New repository secret* → 이름 `KMA_API_KEY`, 값에 인증키(Decoding 키)를 넣으면 이후 빌드되는 APK에 키가 들어가서 설정 입력 없이 바로 연결됩니다. 키는 코드에 남지 않습니다.
- 국립해양조사원 API는 공공데이터포털(`apis.data.go.kr/1192136/...`)로 이전 중입니다. 새 방식 키를 받았다면 `data/TideApi.kt`의 `fetchKhoa()` 주소와 파싱 부분만 새 활용가이드에 맞게 바꾸면 됩니다.

## 3. 점수 계산 방식 (`scoring/ScoreEngine.kt`)

기본 **50점**에서 아래 요인을 더하고 뺍니다. 앱 상세 화면에서 항목별 가감 내역을 그대로 볼 수 있습니다.

| 요인 | 내용 | 범위 |
|---|---|---|
| 시즌 | 어종별 월별 적합도 | −12 ~ +12 |
| 수온 | 적정 범위 +12 / 가능 범위 +2 / 범위 밖 −15 | |
| 대표 어종 | 포인트 대표 어종이 아니면 | −10 |
| 시간대 | 피딩타임(일출·일몰), 볼락은 밤, 벵에돔은 낮 | −12 ~ +15 |
| 조류 | 들물/날물 진행률, 정조 감점, 감성돔·볼락은 중~끝들물 가점 | −6 ~ +14 |
| 물때 | 조금(약함) 감점, 중간 물때 가점 | −5 ~ +8 |
| 바람 | **포인트가 바라보는 방향 기준** 맞바람이면 크게 감점 | −30 ~ +4 |
| 파고 | 감성돔은 0.5~1.2m 포말 가점, 2m 이상 위험 | −30 ~ +6 |
| 비 | 강수 예보 | −4 |

**위험 조건**(풍속 12m/s 이상, 파고 2m 이상, 맞바람+파도 등)이면 점수를 15점 이하로 묶고 경고를 표시합니다.

어종별 기준값은 `scoring/Species.kt`에서 숫자만 바꿔 조정할 수 있습니다.


## 3-1. 포인트별 차등 요인 (v0.6)

| 요인 | 내용 |
|---|---|
| 찌낚시 조류 | 들물은 남서(250°), 날물은 북동(60°)으로 흐른다고 보고(감천항 입구 조류 실측: 창조류 250° 1.9노트, 낙조류 060° 1.6노트)(`scoring/Factors.kt`의 `FLOOD_FLOW_DEG`, `EBB_FLOW_DEG`), 포인트가 바라보는 방향과 비교. 조류가 앞으로 뻗으면 +7, 옆으로 흐르면 +3(곶부리 +3 추가), 갯바위로 받히면 −6 |
| 지형 × 물때 | 센 조류(사리·중들물)엔 홈통 +5·곶부리 −4, 약한 조류(조금)엔 곶부리 +5·홈통 −3 |
| 어종 × 수심·지형 | 감성돔은 4~6m 여밭 +6(조행기 근거), 벵에돔은 8m 이상 +4, 볼락은 여밭·홈통 +3, 무늬오징어는 곶부리·직벽 +3 |
| 과거 조과 | `assets/catches.json`(공개 조행기) + 앱에서 남긴 내 기록. 물때·계절이 비슷하고 바람·파고·수온·시간대가 비슷할수록 최대 +18. 조행기 날짜의 바람·파고·수온은 휴대폰에서 Open-Meteo 과거자료로 한 번 받아 저장 |

| 은파낚시 밴드 조황 | 선장 일일 조황 약 70일치(2025.8~2026.10)를 날짜·어종·조황 등급으로 요약해 `catches.json`에 포함(개인정보·원문 미포함). 부진했던 날과 비슷한 조건이면 감점(최대 −8) |
| 물돌이 | 밴드 조황에서 대물 감성돔은 물돌이 전후 입질이 반복 확인 → 감성돔은 시간대에 만조·간조가 들어 있으면 +7, 정조 감점 없음 |
| 남서풍 | 남서풍에 수온이 내려가 조황이 떨어진 기록 → 남서풍 4m/s 이상 −3 |

점수는 가감 합계를 곡선으로 변환합니다(합계 +38 ≈ 50점, +60 ≈ 72점).

### 조과 기록 남기기
포인트 상세 화면 아래 **내 조과 기록하기**에 마릿수를 넣고 저장하면, 그 시간대의 물때·바람·파고·수온이 함께 저장되고 다음부터 비슷한 조건일 때 그 포인트 점수가 올라갑니다. 기록이 쌓일수록 정확해집니다.

## 3-2. 지도·디자인 (v0.8)

- 포인트 상세 맨 위에 **위성지도**(osmdroid + Esri 위성사진, API 키 불필요). 번호 원 = 포인트, 색 = 점수, 점선 = 바라보는 방향
- 홈의 **목록/지도** 전환으로 27개 포인트를 지도에서 한눈에 보고, 원을 누르면 상세로 이동
- 상세 지도 오른쪽 위 **위치 수정** → 지도에서 실제 자리를 탭하면 그 좌표로 저장(앱 안에 저장, 확인된 위치로 표시)
- 디자인: 심해 그라데이션 헤더와 파도, 하루 **물때 곡선**(지금 시각 표시), 원형 **입질 지수** 게이지, 바람 화살표, 찌 모양 앱 아이콘

## 3-3. 윈디 (v0.9)

- 홈 아래쪽 **바람·파도 흐름** 카드: 윈디 임베드 지도(무료)로 바람·파도·너울·돌풍 애니메이션 보기 (점수 계산에는 사용 안 함)
- 포인트 상세의 **윈디에서 보기** 버튼: 윈디 앱(없으면 웹)이 그 포인트 위치로 열림

## 3-4. 오늘의 공략법 (v0.10)

포인트 상세에서 시간대를 고르면, 그 시간대의 물때·조류 방향·바람·파도·어종에 맞춰 찌낚시 공략을 문장으로 보여줍니다 (`scoring/Tactics.kt`).
- 어디를 노리나: 포인트별 공략 지점(조경지대·여밭 끝자락·수로 등)과 거리·수심 – 지도에 원으로 표시
- 조류와 밑밥: 조류가 공략 방향 기준 어느 쪽으로 흐르는지 → 밑밥을 조류 위쪽에 뿌려 동조
- 채비: 전유동/B조법/반유동/잠길찌 선택, 찌 호수, 찌밑 수심
- 미끼(월별), 타이밍(물돌이·일출·일몰)
- `facingDeg`는 이제 '공략 방향', `target`/`targetDistance`는 공략 지점

## 3-5. 조과 데이터 반영 방식 (v0.11)

- **포인트 기록**(번호나 서편·동편 같은 방향이 있는 기록): 그 포인트 1.0, 35m 이내·공략 방향 비슷 0.45, 70m 이내·같은 지형 0.2, 같은 방향 기록 0.5 가중 → 포인트 순위를 바꿈
- **두도 전체 조황**(밴드 일일 조황처럼 포인트 없는 기록): '두도 전체' 한 줄로 모든 포인트에 같은 값(−8~+10) → 순위는 바꾸지 않고 그날 전체 수준만 반영
- 홈 아래 **조과 데이터** 카드에 데이터 건수 표시, 내 기록은 **내 기록 보내기**로 JSON 공유 → `catches.json`에 합쳐 모든 사용자에게 반영

## 3-6. 찌낚시 기법 보강 (v0.12)

- 공략법에 **밑밥 운용**(수온별 배합 비율, 베이스 밑밥 미리 깔기, 벵에돔 선밑밥 시간차)과 **입질이 없을 때**(미끼 상태별 수심·채비 조정, 잠길찌 전환) 추가
- 벵에돔: 띄울낚시/잠길찌 수온 기준, 목줄 1~1.2호·봉돌 바늘 위, 잡어 많을 때 B찌 L조법
- 감성돔: 저수온기(13.5°C 미만) 고부력 원투·굵은 목줄, 남향·깊은 자리 가점
- 점수: 부이 수온의 **24시간 변화** 반영(+0.3°C 이상 가점, −0.5°C 이하 감점), 벵에돔 적정 수온 18~24°C

## 3-7. 시간별 확률 모델 (v0.13)

- **순위 = 05~13시 평균 확률.** 1시간마다 그 시각의 조건으로 점수를 내고 평균
- 포인트 고정 성격(`scoring/PointModel.kt`): 섬 중심 대비 위치·공략 방향·지형으로 **들물/날물/양물 포인트** 판정
  (조류가 공략 방향으로 뻗음 1.0 · 섬 하류 쪽 조경지대 0.85 · 갯바위 따라 흐름 0.6 · 받힘 −0.6), **너울 노출도**(남쪽 외해 1.0 ~ 북쪽 0.35)
- 시간별: 그 시각 들물/날물 × 포인트 성격 × 조류 세기, 물돌이(감성돔 +9), 해 뜰 무렵, 그 시각 바람(맞바람 판정), 체감 파고(외해 파고 × 노출도)
- 계절: 수온 적합도(곡선), 수온별 선호 수심(감성돔 20°C↑ 3~8m, 15~20°C 4~8m, 13.5~15°C 6~12m, 그 아래 8~15m)과 포인트 수심 겹침, 어종×지형×계절
- 과거 조과(포인트 기록·두도 전체 조황)

## 4. 포인트 수정·추가 (`app/src/main/assets/points.json`)

현재 **송도 두도(부산 서구 암남동) 1~18번, 0.5번 포인트, 직벽** 총 27곳이 들어 있습니다. 번호와 수심은 두도 포인트 지도(송도 은파낚시) 기준입니다.

⚠ **좌표와 바라보는 방향은 지도 사진에서 추정한 값입니다.** 지도에서 실제 위치를 찍어 고쳐주세요.

- `depthMin`, `depthMax`: 수심(m). 10m 이상 포인트는 사리 때 조류 감점을 받지 않습니다.

- `facingDeg`: 갯바위가 바다를 바라보는 방향(0=북, 90=동, 180=남, 270=서). 바람 점수에 직접 쓰이므로 가장 중요한 값입니다.
- `species`: 그 포인트의 대표 어종 (감성돔, 벵에돔, 볼락, 무늬오징어)
- 수정 후 `"coordVerified": true`로 바꾸면 앱의 좌표 경고가 사라집니다.

### 실제 조차로 물때 세기 (웹, 0.15 이후)
GitHub Pages(실시간 모드)에서는 Open-Meteo 해수면 예보의 만조·간조 높이 차를 쓴다. 05~13시에 걸친 조석 구간의 평균 조차를 예보 기간 평균 조차와 비교해 조류 세기(0~100%)를 정한다(사리 ≈ 평균의 1.5배, 조금 ≈ 0.5배). 시간별 점수도 그 시간이 속한 구간의 조차를 쓴다. 해수면 예보가 없으면 물때(월령) 계산값을 그대로 쓴다. 상단에 "조차 (05~13시)"와 두 값을 같이 보여준다.

### 조류 방향 = 해류 예보 (웹, 0.16)
실시간 모드에서는 Open-Meteo 해양 API의 `ocean_current_velocity/direction`(Copernicus SMOC: 조류+해류+파랑류 합성, 윈디 해류 레이어와 같은 계열)을 시간별로 받아, 그 시간에 실제로 흐르는 방향으로 포인트 적합도를 계산한다. 들물/날물 대표 방향(포인트 성격 판정용)도 예보 기간 동안 들물·날물 중간(진행 20~80%) 시간의 해류를 벡터 평균해서 정한다. 예보가 없으면 감천항 실측값(들물 250°, 날물 60°)을 쓴다.

### 확률 색 (0.16)
높음→낮음: 파랑(75↑ 강력 추천) · 초록(62↑ 좋음) · 노랑(50↑ 보통) · 주황(38↑ 낮음) · 빨강(38 미만 비추천). 너울·강풍 위험 시간은 회색.

### 앱에도 해류 예보·실제 조차·너울 방향 (0.17)
- `data/MarineApi.kt`: Open-Meteo 해양 API(키 불필요)에서 해류(조류 포함, SMOC)·너울 방향·해수면을 받는다(30분 캐시).
- 들물/날물 대표 방향은 예보 기간 들물·날물 중간 시간의 해류 벡터 평균으로 정하고(`Factors.FLOOD_FLOW_DEG/EBB_FLOW_DEG`가 바뀜), 시간별 점수는 그 시간의 실제 흐름 방향·세기를 쓴다. 예보가 없으면 감천항 실측 기본값(들물 250°, 날물 60°).
- 조류 세기: 조석표 높이가 있으면 05~13시 실제 조차로(부산 조금 ≈ 40cm, 사리 ≈ 120cm), 없으면 해수면 예보의 조차를 예보 기간 평균과 비교해서 정한다.
- 너울이 정면에서 오면 체감 파고 ×1.2, 등지면 ×0.7.

### 부수 어종: 참돔·농어 (0.18, 초기값)
두도 밴드 조황에는 아직 참돔·농어 기록이 없어 일반적인 남해 갯바위 기준 초기값이다. 대상어에서 고를 때만 계산하고(‘최적 어종’에는 안 들어감), 포인트 대표 어종 목록 대신 지형·노출도로 자리를 판정한다.
- 참돔: 적정 수온 16~23°C, 5~6월·10월 최성기. 외해 정면·수심 10m 이상 본류대, 센 조류(사리)·조류가 앞으로 뻗는 시간, 해 뜰 무렵. 정조에는 감점.
- 농어: 적정 수온 14~22°C, 5~6월·10~11월. 포말 지는 곶부리·여밭, 체감 파고 0.8m 이상, 적당히 탁한 물색, 새벽. 잔잔하거나 맑으면 감점.

### 조류 판정 수정·입질 지점 (0.18.1)
- 두도 앞 해류 예보는 대마난류 때문에 하루 종일 북동쪽으로 치우친다(들물 때도 약한 북·북동류). 이 값을 그대로 평균 내면 들물 방향이 북북동(15°)으로 잘못 나와 서편 포인트가 들물 포인트로 뒤바뀌는 오류가 있었다. 이제 예보 기간 전체 평균(해류)을 빼고 조석 성분만으로 들물/날물 방향을 정한다(검증: 들물 ≈ 240°, 날물 ≈ 60°, 감천항 실측과 일치). 들물·날물이 120° 이상 벌어지지 않으면 기본값을 쓴다.
- 시간별 점수와 지도 화살표는 그 시간의 실제 흐름(해류 포함)을 쓴다. 앱 지도 화살표가 들물 때 엉뚱한 방향을 가리키던 것도 이것으로 고침.
- 해수면 예보로 구한 만조·간조는 부산 조석표보다 약 24분 빨라서 보정.
- 입질 지점: 기본 공략 지점에서 그 시간 흐름을 따라 밑밥·채비가 흘러가 모이는 곳으로 옮겨 표시한다. 바다 쪽으로 흐르면 흐름 방향으로 4~14m(곶부리 1.2배, 여밭 0.8배, 홈통 0.4배), 갯바위 쪽으로 받히거나 직벽이면 갯바위와 나란히, 공략 거리는 0.7배로 가깝게. 흐름이 약하면 기본 지점.
- 포인트 좌표를 위성사진과 대조: OSM 해안선 기준으로는 모두 갯바위 위(평균 1~2m)이고, 위성사진은 OSM보다 북쪽 약 8m·동쪽 약 6m 밀려 있어 좌표는 그대로 둠.

### 감성돔 계절별 지형 (0.18.2)
봄 오름(3~4월) 조류 잘 가는 여밭·곶부리 +4 → 산란기(5~6월) 해조류 붙은 얕은 홈통·여밭 +3 (5월은 금어기 −15, 방생 안내) → 고수온기(7~8월) 조류 소통 좋은 곶부리 +3·물 고이는 홈통 −2 → 가을 회유(9~11월) 여밭 +6 → 겨울(12~2월) 깊은 직벽·수로 +5·얕은 자리 −3. 수온 13.5°C 미만이면 계절과 상관없이 깊은 직벽·수로 +6.

### 포인트 위치 재조정 (0.18.4)
사용자가 앱 지도에서 직접 옮긴 위치(스크린샷 14장)를 Esri 위성 타일과 영상 정합(템플릿 매칭, 배율 2.3배)으로 좌표로 변환해 28개 포인트 전부 반영. 움직이지 않은 18·17.5번이 정확히 겹쳐 정합 확인. 바라보는 방향(facingDeg)은 새 위치에서 위성사진의 바다 방향(반경 6~30m 바다 픽셀 가중 평균)으로 다시 계산. 10번과 직벽은 위아래가 바뀜(10번이 북쪽).

### 포인트 정리 (0.18.5)
사용자 요청으로 10번·14번 삭제, 4번과 4.5번 사이 서편 곶부리에 4.3번 추가(위성사진에서 곶부리 끝 바위 위, 서쪽 279° 공략, 수심 5~8m 추정). 포인트 27곳.

### 벵에돔 수온 보정 (0.18.6)
벵에돔은 하루 수온 1°C 이상 하락 시 추가 −4(떠오르지 않음). 6~9월 수온 17°C 미만이면 '여름 냉수대 의심' 벵에돔 −6·감성돔 −3 (부산·남해 동부 냉수대).

### 물때별 자리 이동 (0.18.8)
포인트에 altSpots(들물 flood / 날물 ebb 때 옮겨 설 자리: 위치·방향·지형·공략 거리)를 넣으면, 그 물때 시간에는 원래 자리와 옮긴 자리를 둘 다 계산해 점수가 높은 쪽을 쓰고 지도·입질 지점도 그 자리로 보여준다. 첫 적용: 14.5번 들물 때 남쪽 홈통(곶부리 남쪽 약 20m, 동쪽 95° 공략, 공략 8m).

### 현지 경험 물때 성격 (0.18.9)

### 밴드 조황 역검증 (0.19.0)
은파 밴드 감성돔 조황 57일(2025-08~2026-10)을 Open-Meteo 과거 날씨·해양 자료로 다시 계산해 조황 등급과 비교. 기존 모델은 순위상관 0.10으로 거의 못 맞혔고, 좋은 날은 조차가 크고(평균 112cm vs 부진 85cm) 오전(06:30~11:30)에 만조가 드는 경우가 많았음(82% vs 44%). 감성돔만 물때 점수를 조정: 조차 비율 0.6 이상 +9(얕은 자리 사리 감점 제거), 0.2 미만 −12, 0.35 미만 −5, 오전 만조 +6. 조정 후 0.29(과거 기록 포함 0.31). 표본이 작아 앞으로 조황이 쌓이면 다시 검증.
